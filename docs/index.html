1 Purpose

Economic interdependence and financial globalization have intensified the need for accurate measures of shock transmission across macroeconomic and financial systems. To this end, the JointShocks R package provides researchers and practitioners with robust tools to estimate the joint spillover metrics proposed in Lastrapes and Wiesen (2021) and Lastrapes and Wiesen (2025).

Additionally, it offers functionalities to compute the joint impulse response function and the joint forecast error variance decomposition introduced in Wiesen and Beaumont (2024).

For comparative purposes, the package also includes:

  • The generalized spillover index and metrics of Diebold and Yilmaz (2012) and Diebold and Yılmaz (2014), and
  • The generalized impulse response function and generalized forecast error variance decomposition of Koop, Pesaran, and Potter (1996) and Pesaran and Shin (1998).

The goal of this package is to streamline the computation of these metrics-across both full-sample and rolling window applications-within a user-friendly and reproducible framework. It bridges theoretical contributions from the academic literature with accessible implementation tools for empirical work in macro-finance, banking, and monetary economics.

The remainder of this documentation proceeds as follows: Section 2 briefly discusses the installation procedure. Section 3.1 provides and discusses the replication of key results from Wiesen and Beaumont (2024), including the estimation of their Joint Impulse Response Functions (jIRFs). This involves implementing their bootstrap procedures, as well as computing the Generalized Impulse Response Functions (gIRFs) and the Generalized Forecast Error Variance Decomposition (gFEVD). Section 3.2 focuses on estimating the joint spillover metrics as developed in Lastrapes and Wiesen (2021) Lastrapes and Wiesen (2025) and the generalized spillover metrics in Diebold and Yilmaz (2012) and Diebold and Yılmaz (2014).

2 Installation Procedure

To begin using the JointShocks package, install it from GitHub using the devtools package (only needed once):

#install.packages("devtools")
devtools::install_github("JohnsonOliyide/JointShocks")

Then load it as follows:

library(JointShocks)

Because the package relies on vector autoregressions, be sure to load the vars package:

library("vars")

2.1 Loading your own data

The package currently supports data files in .csv or .xlsx format. The first column must represent dates. To read .xlsx files, load the readxl package:

library("readxl")

To load your own dataset, use the read_data() function, pointing it at the path to your file and specifying the format of the dates in your file’s first column. For example, if you had a file called "my_data.csv" with dates formatted like 1/5/2017, you would run:

Data_date <- read_data("my_data.csv", date_format = "%m/%d/%Y")

Data <- Data_date$Data
date <- Data_date$date

This returns a list with Data (a matrix of your variables) and date (a vector of the corresponding dates), ready to be used with vars::VAR() and the rest of the functions in this package.

2.2 Sample data used in this vignette

For replication, the remainder of this vignette uses datasets bundled with the package from Wiesen and Beaumont (2024), which contain the volatility of eleven major banks from three different periods: pre-pandemic (1/5/2017-1/31/2020), pandemic (2/3/2020-2/3/2021), and full sample (1/5/2017-2/3/2021). The banks used are Bank of America (BAC), Bank of New York Mellon (BK), Barclays (BCS), Citigroup (C), Credit Suisse (CS), Deutsche Bank (DB), Goldman Sachs (GS), JP Morgan Chase (JPM), Morgan Stanley (MS), State Street (STT), and Wells Fargo (WFC).

Load the pre-pandemic sample data as follows:

data(Volatility_data_pre)

Data <- Volatility_data_pre
date <- attr(Volatility_data_pre, "date")

3 Empirical Analysis

3.1 Wiesen and Beaumont (2024) -The Joint Impulse Response Function and Joint Forecast Error Variance Decomposition

We refer users to Wiesen and Beaumont (2024) for a complete explanation of the methodology and its empirical contributions.

Estimate a VAR model

#------------- Run a VAR model------
# Estimate VAR with 1 lag, as used in the paper
VAR_model <- VAR(Data, p = 1, type = "const")

3.1.1 Joint Impulse Response Function (jIRF)

To compute the joint impulse response function involving shocks from Barclays (BCS), Credit Suisse (CS), and Deutsche Bank (DB), run this:

jIRF <- run_full_jIRF(VAR_model, from_set = c("BCS", "CS", "DB"), H = 8)

You can plot the jIRF response of Bank of America. The result it produces shows how the equity market of Bank of America respond over the next eight days to a joint, simultaneous one standard deviation shocks from Barclays, Credit Suisse and Deutsche Banks. Since jIRF is a labeled matrix, we can plot it directly using base R:

# Plot jIRF for specific response
horizon <- 0:8
plot(horizon, jIRF["BAC", ], type = "l", lwd = 3, col = "#33a02c",
     xlab = "Horizon", ylab = "Response",
     main = "Joint IRF: Response of BAC to Joint Shock",
     cex.main = 1.3, cex.lab = 1.1, cex.axis = 0.95)
abline(h = 0, col = "gray40", lty = 2)
grid()

If you’re interested in the gIRF of Pesaran and Shin (1998) without confidence bounds, run:

gIRF <- run_full_gIRF(VAR_model, H = 8) # Run the gIRF

This returns the entire set of gIRF results, showing how each variable responds to a one-standard-deviation shock in every other variable.

To visualize a specific response-shock pair — for instance, the effect of a shock from Barclays on Bank of America:

plot(horizon, gIRF["BAC", "BCS", ], type = "l", lwd = 3, col = "#1f78b4",
     xlab = "Horizon", ylab = "Response",
     main = "Response of BAC to Shock in BCS",
     cex.main = 1.3, cex.lab = 1.1, cex.axis = 0.95)
abline(h = 0, col = "gray40", lty = 2)
grid()

You may compare the jIRF against individual gIRFs using:

# Combined IRFs as in jIRF paper
from_set <- c("BCS", "CS", "DB")
g_colors <- c("blue", "orange", "purple")
j_color <- "black"
g_vals_list <- lapply(from_set, function(s) gIRF["BAC", s, ])
y_range <- range(c(unlist(g_vals_list), jIRF["BAC", ]))
plot(horizon, jIRF["BAC", ], type = "n",
     ylim = y_range, xlab = "Horizon", ylab = "Response",
     main = "IRFs: BAC to Joint & Individual Shocks",
     cex.main = 1.3, cex.lab = 1.1, cex.axis = 0.95)
for (i in seq_along(from_set)) {
  lines(horizon, g_vals_list[[i]], col = g_colors[i], lwd = 2.5, lty = 1)
}
lines(horizon, jIRF["BAC", ], col = j_color, lwd = 2.5, lty = 2)
abline(h = 0, col = "gray40", lty = 2)
legend("topright", legend = c(paste0("gIRF: ", from_set), "jIRF"),
       col = c(g_colors, j_color), lty = c(rep(1, length(from_set)), 2), lwd = 2.5, cex = 0.85)
grid()

Note: To explore a different set of shock contributors, rerun run_full_jIRF() with a new from_set and recompute jIRF/gIRF before re-plotting.

3.1.2 Joint Forecast Error Variance Decomposition (jFEVD)

Users of this package can also calculate the joint forecast error variance decomposition (jFEVD) of Wiesen and Beaumont (2024). This jFEVD measures the proportion of a variable’s forecast error variance that can be jointly explained by a specified set of multiple shocks.

We recommend referring to Wiesen and Beaumont (2024) for a detailed explanation of the model’s theoretical advantages and empirical applications.

To illustrate, the jFEVD result can be interpreted as follows: approximately 16% of the \(H\)=30 step forecast error variance of Bank of America (BAC) is attributable to joint shocks from Barclays (BCS), Credit Suisse (CS), and Deutsche Bank (DB).

#-------------Joint FEVD------
# Run and present jFEVD result
jfevd <- run_full_jFEVD(VAR_model, from_set = c("BCS", "CS", "DB"), H = 30)
jfevd

## 0.15952241 0.05223781 0.96668595 0.16460344 0.95693593 0.94891627 0.14332551 
##        JPM         MS        STT        WFC 
## 0.16926043 0.13025529 0.05798865 0.08725354

3.1.3 Generalized Forecast Error Variance Decomposition (gFEVD)

Another important concept is the gFEVD of Koop, Pesaran, and Potter (1996) and Pesaran and Shin (1998). This decomposition is embedded in the genspill() function and captures how shocks in one variable contribute to the forecast error variance of another.

While the genspill() function produces several outputs (fully discussed in Section 3.2), our current interest is solely in the gFEVD matrix.

Each element \((i,j)\) of the matrix quantifies the proportion of the \(H\)-step forecast error variance of variable \(i\) that can be attributed to shocks originating from variable \(j\).
For instance, using pre-pandemic data, the gFEVD results suggest that 7.2% of Bank of America’s forecast error variance is explained by shocks from Barclays (BCS), and about 6% by shocks from Deutsche Bank (DB).

3.1.4 Bootstrapping

The interpretations provided above remain valid; however, bootstrapping allows us to compute confidence intervals around the impulse response functions, adding a layer of statistical inference.

Bootstrapping is split into four functions. First, bootstrap_VAR() bootstraps the VAR model itself, saving the constant, VAR coefficient matrices, and shock covariance matrix for each of B iterations. The first iteration is always the original (non-resampled) fitted parameters, so the original IRF can be recovered alongside the bootstrap distribution. Then, bootstrap_gIRF(), bootstrap_jIRF(), and bootstrap_gIRF_sum() each take the bootstrapped VAR parameters and compute confidence intervals for the generalized IRF, joint IRF, and sum of generalized IRFs, respectively — for whichever response variable you request.

Make sure you have sufficient memory available, as bootstrapping can be computationally intensive depending on the number of iterations (B). The default is B = 10000, and the default confidence interval is 90%, but you can set any desired level using the CI argument.

In the example below, we bootstrap the VAR with 500 iterations.

# B is the number of bootstrap iterations (default = 10000)
# VAR_model is the object estimated using the VAR function
boot_model <- bootstrap_VAR(VAR_model, B = 500)
## Bootstrap iteration: 200 
## Bootstrap iteration: 400

With boot_model computed once, we can now compute the bootstrapped confidence interval for the jIRF, the gIRF sum, or an individual gIRF, for any response variable, without re-running the bootstrap each time.

Joint IRF (jIRF) with confidence interval

# response is the response variable
# shocks is the set of variables where the joint shocks originate
# H is the H-step ahead
# CI sets the confidence interval level (default = 0.90)

3.1.5 Replicating Figure 3 of Wiesen and Beaumont (2024)

We can replicate the pre-pandemic column of Figure 3 of Wiesen and Beaumont (2024), which shows the jIRF (with confidence interval), the three individual gIRFs, and the sum of gIRFs, due to joint shocks from Barclays (BCS), Credit Suisse (CS), and Deutsche Bank (DB), for a given response variable.

plot_fig3_panel <- function(boot_model, response, main) {
  shocks <- c("BCS", "CS", "DB")
  H <- 8
  CI <- 0.80
  horizon <- 0:H

  jIRF_CI <- bootstrap_jIRF(boot_model, response = response, shocks = shocks, H = H, CI = CI)
  gIRF_sum_CI <- bootstrap_gIRF_sum(boot_model, response = response, shocks = shocks, H = H, CI = CI)
  gIRF_list <- lapply(shocks, function(s) bootstrap_gIRF(boot_model, response = response, shock = s, H = H, CI = CI))

  g_colors <- c("blue", "red", "darkgreen")
  g_ltys <- c(3, 2, 4)

  y_range <- range(c(jIRF_CI$lower, jIRF_CI$upper,
                      gIRF_sum_CI$lower, gIRF_sum_CI$upper,
                      sapply(gIRF_list, function(g) range(g$lower, g$upper))))

  plot(horizon, jIRF_CI$original, type = "n", xlim = c(0, H), ylim = y_range,
       xlab = "h steps ahead", ylab = "impulse response", main = main,
       cex.main = 1.1, cex.lab = 0.95, cex.axis = 0.9)

  polygon(c(horizon, rev(horizon)), c(gIRF_sum_CI$lower, rev(gIRF_sum_CI$upper)),
          col = adjustcolor("tan", alpha.f = 0.5), border = NA)
  polygon(c(horizon, rev(horizon)), c(jIRF_CI$lower, rev(jIRF_CI$upper)),
          col = adjustcolor("gray50", alpha.f = 0.5), border = NA)

  lines(horizon, gIRF_sum_CI$original, col = "#9A6324", lwd = 2)
  lines(horizon, jIRF_CI$original, col = "black", lwd = 2, type = "o", pch = 16)
  for (i in seq_along(shocks)) {
    lines(horizon, gIRF_list[[i]]$original, col = g_colors[i], lwd = 2, lty = g_ltys[i])
  }
  abline(h = 0, col = "black", lty = 2)

  legend("topright", cex = 0.6,
         legend = c("jIRF: shocks from BCS, CS, & DB", "80% CI for jIRF",
                    "gIRF: shock from BCS", "gIRF: shock from CS", "gIRF: shock from DB",
                    "sum of gIRFs", "80% CI for sum of gIRFs"),
         col = c("black", "gray50", g_colors, "#9A6324", "tan"),
         lty = c(1, NA, g_ltys, 1, NA), lwd = c(2, NA, 2, 2, 2, 2, NA), pch = c(16, NA, NA, NA, NA, NA, NA),
         fill = c(NA, adjustcolor("gray50", alpha.f = 0.5), NA, NA, NA, NA, adjustcolor("tan", alpha.f = 0.5)),
         border = NA, merge = TRUE, seg.len = 2)
}

Now produce the first panel of Figure 3’s pre-pandemic column, the pre-pandemic impulse response of Bank of America:

plot_fig3_panel(boot_model, "BAC", "Pre-Pandemic Impulse Response of Bank of America")

The remaining panels of Figure 3 (Citigroup and JP Morgan Chase) can be reproduced the same way, by calling plot_fig3_panel() with response = "C" or response = "JPM".

3.2 Lastrapes and Wiesen (2021) and Lastrapes and Wiesen (2025) - Joint Spillover Metrics

We refer users to the works of Lastrapes and Wiesen (2021) and Lastrapes and Wiesen (2025) to understand the concept of joint spillover metrics, and to Diebold and Yilmaz (2012) and Diebold and Yılmaz (2014) for the generalized variant.

As with the joint impulse response function and the joint forecast error variance decomposition (from section 3.1), you must estimate a K-variable VAR model first before computing the (non rolling window) spillover metrics. As illustrated previously, say you want to load the pre-pandemic bank volatility data from Wiesen and Beaumont (2024). For more information about this dataset, see section 3.1.

#Load and prepare the data as follows:
data(Volatility_data_pre)

Data <- Volatility_data_pre
date <- attr(Volatility_data_pre, "date")
#------------- Run a VAR model------
# Estimate VAR with 1 lag, as used in the paper
VAR_model <- VAR(Data, p = 1, type = "const")

Once the VAR_model object above is available, the jointspill() function can be used to compute the joint spillover metrics.

The jointspill() function produces the following results:

  1. The K x K gFEVD matrix (gFEVD)
  2. The joint total spillover from all others to variable i (jnt_from_others_to_i)
  3. The joint total spillover from variable i to all others (jnt_to_others_from_i)
  4. The joint net total spillover (jnt_net)
  5. The joint spillover index (jSOI)
  6. The lambda scaling factor (lambda)
  7. The scaled gFEVD matrix (gFEVD_tilde)

As before, H denotes the number of forecast periods ahead (i.e., the forecast horizon).

jointspill_results <- jointspill(VAR_model, H = 30)

If users want to extract any of the seven outputs calculated by jointspill(), they can use the $ extraction operator. For example, jointspill_results$gFEVD returns the K x K generalized forecast error variance decomposition (gFEVD) matrix.

Additionally, users can easily view outputs (1) through (5) using the generic summary() function. This summary presents a well-structured table:

  • The upper-left K x K portion contains the gFEVD matrix.
  • The last column shows the joint total spillover from all others to each variable (jnt_from_others_to_i).
  • The second-to-last row displays the joint total spillover from each variable to all others (jnt_to_others_from_i).
  • The final row contains the joint net total spillovers (jnt_net).
  • The joint spillover index (jSOI) is reported in the bottom-right corner of the table.

This summary can be generated using:

summary(jointspill_results)

Similar to the joint spillover results, the generalized spillover metrics of Diebold and Yilmaz (2012) and Diebold and Yılmaz (2014) can also be estimated using the genspill() function.

This function returns the following outputs:

  1. The K x K generalized spillover table (gSOT)
  2. The generalized total spillover from all others to variable i (gen_from_others_to_i)
  3. The generalized total spillover from variable i to all others (gen_to_others_from_i)
  4. The generalized net total spillover (gen_net)
  5. The generalized spillover index (gSOI)

You can compute these metrics by running:

#Compute the generalized spillover results using the estimated VAR model with a time horizon of H=30.
genspill_results <- genspill(VAR_model, H = 30)

As in Diebold and Yilmaz (2012) and Diebold and Yılmaz (2014), users can use the generic summary() function to generate a summarized version of the generalized spillover results.

  • The last row contains the generalized net total spillover.

3.2.1 Rolling Window Analyses

To perform rolling window analyses for either the joint spillover metrics or its generalized variant, users must first estimate a rolling window VAR model. The parameter win specifies the window size. For example, the following line of code will estimate a rolling window VAR model of one lag and a window length of 150 periods using the pre-pandemic bank volatility data from previous sections

# p is the lag
# win is the window size
# const is TRUE if you want to include a constant, or FALSE if not.
# dates is the date vector extracted earlier (attr(Volatility_data_pre, "date"));
# VAR_roll() uses it (together with win) to compute the end-of-window date for each
# rolling window, which is carried through as end_of_window_date in its output.
rolling_model <- VAR_roll(data = Data, p = 1, win = 150, const = TRUE, dates = date)

If users want to extract any of the four outputs produced by the VAR_roll() function, they can do so using the $ extraction operator. The available components are:

  1. VARcoeff - VAR coefficient matrices for each rolling window
  2. constant - Intercepts for each rolling window
  3. Sigma - Residual (shock) covariance matrices for each rolling window
  4. end_of_window_date - The end-of-window date for each rolling window, computed from the dates and win inputs

For example, rolling_model$VARcoeff will return the rolling VAR coefficients.

Compute the joint spillover results using the rolling window VAR model with a forecast horizon H. The dates input to VAR_roll() should be the date vector extracted earlier (date <- attr(Volatility_data_pre, "date")). The “date” input should not be truncated or shortened. The R code uses the win input together with dates to calculate the end-of-window date for each rolling window.

# H is the horizon.
# jointspill_roll() carries the end-of-window dates through from rolling_model
# (computed by VAR_roll() using the win input), so no separate dates argument is needed.
joint_spill_results_roll <- jointspill_roll(rolling_model, H = 30)

As an example, if users wish to plot the jSOI over rolling windows, they can run the following.

The command genspill_roll() can be used to compute the generalized spillover metrics over rolling windows. Notice that the arguments of the genspill_roll() command are:

  1. rolling_model - the rolling window VAR object
  2. H - the forecast error horizon

Like jointspill_roll(), the end-of-window dates are carried through from rolling_model, so there is no separate dates argument.

#--------------- Diebold-Yilmaz Spillover rolling window-------
##Compute the generalized spillover results using the rolling window VAR
